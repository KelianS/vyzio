# Instructions de Développement

## Contexte du Projet
Une solution de video-surveillance pour la maison ou les professionnels; **autonome, résiliente et privacy-first**. 
L'objectif est de fournir une reconnaissance faciale IA locale sans dépendre de services cloud tiers pour le traitement des images.
Le projet se différencie par sa souveraineté (Française) et sa vocation plug and play. A destination d'un public non technophiles.

### Engagements
- **Privacy by design** — IA locale, zéro transmission d'images sans consentement
- **Transparence** — Code source ouvert, audit possible
- **Résilience** — Fonctionne sans internet
- **Interopérabilité** — Pas de vendor lock-in
- **Simplicité** — Aucune connaissance technique requise pour l'installation et l'utilisation

## Conventions & Principes
- **Clean code** — Lisibilité, simplicité, modularité
- **Language(s)** — .NET 10 / C# pour le backend. TypeScript + React + Vite pour le frontend. Python si pas le choix / pour IA.
- **Package manager frontend** — pnpm obligatoire (pas npm, pas yarn)
- **Privacy first** — Jamais envoyer d'images sans consentement explicite
- **Modulaire** — Chaque composant (caméra, stockage, IA) doit être pluggable, micro-services ou module indépendant
- **Tests** — Coverage obligatoire : tests unitaires (use cases mockés via NSubstitute) + tests d'intégration (SQLite in-memory)

## Architecture — Clean Architecture (obligatoire)

Toute nouvelle feature backend doit respecter cette structure de couches. Ne jamais déroger à la direction des dépendances.

```
Core         ← entités domaine + interfaces (ports). Aucune dépendance externe.
Application  ← use cases uniquement. Dépend de Core. Jamais de DbContext ni d'EF.
Infrastructure ← implémentations des interfaces Core (repositories EF, MQTT, HTTP...). Dépend de Core.
Api          ← wiring DI + endpoints Minimal API groupés. Dépend de Application + Infrastructure.
Tests        ← unitaires (NSubstitute, zéro DB) + intégration (SQLite in-memory, EnsureCreated).
```

### Règles strictes
- **Core** : pas d'EF Core, pas d'ASP.NET, pas de packages infra. Entités POCO + interfaces uniquement.
- **Application** : un use case = une classe avec une méthode `ExecuteAsync`. Pas de CQRS ni MediatR. Pas d'accès direct à EF.
- **Infrastructure** : implémente les interfaces de Core. Seule couche autorisée à connaître EF, SQLite, MQTT, etc.
- **Api** : les endpoints sont groupés dans `Endpoints/`. `Program.cs` ne contient que le wiring. Le `DbContext` n'est jamais injecté directement dans un endpoint.
- Les **use cases sont testables sans DB** (mocks NSubstitute sur les interfaces).

### Exemple de flux pour une feature "Profiles"
```
IProfileRepository          (Core/Interfaces)
ProfileRepository           (Infrastructure/Persistence/Repositories) → implémente IProfileRepository
CreateProfileUseCase        (Application/UseCases/Profiles) → reçoit IProfileRepository par DI
ProfilesEndpoints           (Api/Endpoints) → reçoit CreateProfileUseCase par DI
CreateProfileUseCaseTests   (Tests/UseCases) → mock IProfileRepository avec NSubstitute
```
